# Ecosystem Catalogue

Use this skill when maintaining the FDCA ecosystem catalogue data in this
project folder: reconciling the roster, checking taxonomy, enriching member
records, scraping FDCA introduction posts, or rebuilding the generated
dashboard.

## Layout

The skill lives in:

`SKILL/` in the `fdca-ecosystem-catalogue` repository.

Scripts are in `SKILL/scripts/`. They resolve paths relative to the repository:

- `INPUT/` holds the tracked source data and design tokens.
- `OUTPUT/` holds regenerated artifacts such as `index.html` and
  `category-proposals.json`.

## Normal Checks

From the `development/` folder, use:

```bash
python3 SKILL/scripts/merge_member_list.py --check
python3 SKILL/scripts/apply_taxonomy.py --check
python3 SKILL/scripts/validate_catalogue.py --check
python3 SKILL/scripts/build_dashboard.py
```

`merge_member_list.py --check` verifies roster reconciliation without
writing. `apply_taxonomy.py --check` verifies one primary category per
company. `validate_catalogue.py --check` also verifies decision-rule coverage,
bilingual descriptions, publishability and generated-file freshness.
`build_dashboard.py` writes
`OUTPUT/index.html` (Map and List views of the same five-family taxonomy).

## Data Maintenance

Use the maintenance scripts only when the relevant source changes:

- `merge_member_list.py` reconciles `INPUT/fdca-member-list-2026-08-31.txt`
  into `INPUT/fdca-member-registry.json`.
- `apply_taxonomy.py` validates current primary-category values. Historical
  migrations are explicit scripts and never implicit guesses.
- `enrich_members.py --research` fills missing homepages/descriptions using
  Firecrawl and simple domain checks.
- `enrich_members.py --propose` writes
  a versioned `OUTPUT/category-proposals.json` for intake records still marked
  `uncategorised`, pointing to the live taxonomy and rules.
- `enrich_members.py --apply` rejects stale, unknown or unreviewed
  low-confidence proposals before applying one primary category.
- `probe_missing.py` tries to find missing FDCA intro-post links from the
  FDCA sitemap.
- `scrape_blog_posts.py` fills or retries article-body text for members with
  an intro-post link.

Do not treat website-only entries as confirmed members. The roster owns
membership status; fdca.fi owns display names and scraped public details.

## Classification sources

- `INPUT/fdca-categories.json` owns stable slugs, bilingual names and short
  descriptions.
- `INPUT/fdca-classification-rules.json` owns the executable decision sequence.
- `INPUT/company-category-classification-rules.md` and
  `OUTPUT/category-summary.md` are generated by `validate_catalogue.py`.
- `INPUT/DESIGN.md` owns family colours. Never put visual tokens in taxonomy.

Every published company has one primary category. Derive its high-level
family from the taxonomy. If no data-center-specific offer is documented,
classify from the verified general offer; escalate only a genuine tie.
